The Vault

Logins, bank details, cards, IDs and notes, with photos, locked behind one master password. Everything is encrypted on the phone and never leaves it: no account, no cloud, no network.

The stack

Browser-native, nothing rolled by hand

All cryptography is WebCrypto. The only runtime libraries are React and an icon set; everything else, including the Excel and OLE parsers, is local TypeScript.

Architecture

From master password to screen

The master password never touches storage. It derives a key-encryption key that unwraps the data key; only then is the vault decrypted into memory.

How it was built

Six phases

The order the pieces went in, from the crypto core outward. Open a phase to see its steps.

01Crypto coreKey wrapping the way mainstream managers do itcrypto.ts›
  1. 1.1
    KEK from password

    PBKDF2-SHA256 at 600,000 rounds with a random salt; 100,000 is the floor for old files.

  2. 1.2
    Random data key

    A 256-bit DEK is wrapped by the KEK, so a password change re-wraps one key instead of re-encrypting everything.

  3. 1.3
    Seal everything

    AES-GCM with fresh IVs over the vault JSON, each attachment and each snapshot.

  4. 1.4
    v2 envelope

    format: "pwvault", v: 2 with KDF params, wrapped keys, revision counter and timestamp.

  5. 1.5
    v1 read path

    The original single-file format still opens read-only and is migrated forward.

02Storage & sessionSafe saves, locking and historysession.ts›
  1. 2.1
    IndexedDB store

    Envelope, attachments and snapshots, with a localStorage fallback and a persistent-storage request.

  2. 2.2
    Verified writes

    Every save is read back and checked; a failed check raises instead of silently losing data.

  3. 2.3
    Multi-tab safety

    A revision counter detects a vault changed in another tab and refuses to overwrite it.

  4. 2.4
    Auto-lock

    Locks after inactivity or when the app is hidden; copied secrets are cleared from the clipboard.

  5. 2.5
    Snapshots & trash

    Version-history snapshots, earlier passwords kept per item, 30-day trash and undo.

03App shell & screensPhone-first React UIui/›
  1. 3.1
    Shell

    Category tabs, search, favorites and multi-select for bulk move or delete.

  2. 3.2
    Item types

    Logins, bank, cards, IDs and notes, plus free-form extra fields such as PIN or sort code.

  3. 3.3
    Attachments

    Photos and PDFs shrunk on-device, then sealed like every other byte.

  4. 3.4
    Tools

    Built-in TOTP codes, a password health check (weak, reused, old) and a character or word generator.

  5. 3.5
    Theme

    Dark and light themes sized and tested at 412×915.

04ImportersBring the old spreadsheet in, pictures and allimporters/›
  1. 4.1
    CSV & manager exports

    Chrome, Bitwarden, 1Password and Firefox layouts mapped onto vault fields.

  2. 4.2
    XLSX parser

    Zip and sheet XML read locally; every tab becomes a category and pictures stay with their row.

  3. 4.3
    Password-protected Excel

    Compound-file (CFB) reader plus Office Agile and Standard decryption in officecrypto.ts.

  4. 4.4
    Hostile-file limits

    64 MB per part, 256 MB total, 4 M cells and 300 pictures, so zip bombs and lying sizes fail cleanly.

05Two builds, one sourceSingle file and installable PWAvite›
  1. 5.1
    Single-file mode

    password-vault.html: everything inlined, open it straight from disk.

  2. 5.2
    PWA mode

    Hashed assets, manifest, icons and a generated service worker for offline launch.

  3. 5.3
    Fingerprint unlock

    WebAuthn PRF passkey, available once installed on an https origin.

  4. 5.4
    Locked-down headers

    _headers sets a strict CSP, no framing, no referrer, and HSTS.

  5. 5.5
    Release script

    npm run release builds both and copies them to the repo root for static hosting.

06Hardening & verificationRegression suite and screenshot tourtests/›
  1. 6.1
    Unit coverage

    Crypto, session, model, importers, Office decryption, strength, TOTP and health.

  2. 6.2
    Browser flows

    Playwright at phone size: setup, edit, import, backup and restore, PWA install.

  3. 6.3
    v1 → v2 migration

    The original app is a fixture; its vault must open and move across intact.

  4. 6.4
    Hostile fixtures

    Generated bombs, huge rows and web-linked images guard the import limits.

  5. 6.5
    Screenshot tour

    SHOTS=1 run produces the README images from the real app.

Test strategy

What keeps it honest

Run from app/: npm test, npm run typecheck, npx playwright test.

Unit

vitest · jsdom · fake-indexeddb

  • crypto: wrap, unwrap, wrong password, iteration floor
  • session: saves, conflicts, auto-lock, snapshots
  • officecrypto: Agile and Standard encrypted workbooks
  • importers, model, strength, TOTP, health

Hostile inputs

python fixture generators

  • Zip bombs, including ones that lie about their size
  • Huge rows and pictures anchored under headings
  • Web-linked images that must never be fetched
  • Workbooks encrypted by Excel and by LibreOffice

Integration

playwright · chromium · 412×915

  • Flows: setup, add, edit, search, bulk actions, trash
  • Import: real spreadsheets end to end
  • Migration: v1 single-file vault to v2
  • PWA install, offline launch, regressions

Manual

on a real Android phone

  • Install from Chrome and turn on fingerprint unlock
  • Back up, then restore into the installed app
  • Airplane mode: open, unlock, edit, lock
  • Switch apps and confirm it locks itself
